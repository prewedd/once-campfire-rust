# sha2 0.10.9's `asm` feature on aarch64 (00f9744): its ARMv8 SHA-256 backend instead of the
# software rounds. crates/kit/examples/sha256_bench.rs times SHA-256 at the app's sizes; per size the
# median and range of 7 runs of ~64 MB each.
#
# The measurement that matters has to run on ARM (a Pi 5, Graviton, or the ubuntu-24.04-arm runner
# the publish workflow uses), at 62394bb or later, both ways, interleaved, three rounds:
#   cargo run --release -p campfire_kit --example sha256_bench                               # after
#   cargo run --release -p campfire_kit --example sha256_bench --features sha2/force-soft    # before
# `force-soft` selects exactly the code aarch64 ran before (sha2's `soft::compress`, which is also
# what it falls back to without `asm`). Both runs must print the same "digest of every length" line.
# Not measured here: this host has no aarch64 hardware.

# Build check on emulated arm64 (qemu-user via binfmt): a standalone crate with sha2 =0.10.9
# features ["asm"] and this example's code before 62394bb reworded its first line (4 MB per run),
# built in rust:1.98.1-slim-trixie --platform linux/arm64 (a subset of the Dockerfile's
# rust:1.98.1-trixie build stage), then again with sha2/force-soft. sha2-asm's build script
# assembled sha256_aarch64.S with the image's gcc,
# and both builds print the same digest. qemu emulates the SHA-256 instructions with helper calls,
# so the hardware path is slower there than translated scalar code: these timings only show that
# the two builds take different paths, and say nothing about real ARM CPUs.
